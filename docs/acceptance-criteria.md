# 受け入れ基準と監査記録

基準日: 2026-09-11。docsの仕様監査と同期の`request_user_input`で確定した目標契約です。
本書を作成したことは、実装の適合性や以下の試験の合格を意味しません。

## 完成の定義

Wranglerで公開し、公開URLで説明・同意、4場面の回答、DB保存、CSV取得、同じ仕様での途中再開、期限削除まで確認できることを技術完成とします。デプロイコマンドの成功だけでは完成としません。

現在のHello Worldの実装・検証記録は[開発・デプロイ手順](deployment.md)にあります。1試行の接続確認を、4場面の実験の合格証拠に代用しません。
実参加者の募集開始、研究上の必要人数・分析規則の確定、予備実施は別の研究準備です。未確定の場合は実参加者用受付を停止し、合成データの技術検証は別のローカル・検証用公開環境で行います。

本書は合否判定、[データ契約](data-contract.md)は保存・APIの動作、[研究計画](research-plan.md)は研究上の位置づけを記述します。説明が食い違う場合は合格にせず、文書を整合させてから判定します。

## 監査で確定した判断

| ID | 発見した論点 | 最終判断 |
| --- | --- | --- |
| D01 | 1行1試行では0回答の参加者を集計できない | 試行CSVに加えて保持期限内の全セッションCSVを出力する |
| D02 | 保存確認だけの再開まで課題再開として除外するか不明 | 感度分析の除外は課題の再開。保存確認だけでは除外しない |
| D03 | 4回答保存後の別の完了要求が失われると未完了になる | 4件保存とDBの完了更新を一体化し、完了APIを廃止する |
| D04 | 24時間のアクセス期限と期限後の完了確認が衝突する | 期限後の確認には対応しない。完了したDBデータは完了のまま保持する |
| D05 | 旧schema維持と非対応更新時の再開停止が併記されている | 参加途中の仕様更新を明示的に想定外とする |
| D06 | デプロイ成功と機能完成と研究準備が混在している | 公開後の実動作まで技術完成に含め、研究準備の確定は含めない |
| D07 | PC向けの対象と表示幅が曖昧 | 検証時のChrome安定版、幅1024 CSS px以上、キーボード操作を確認する |
| D08 | 自動再送の回数・待機時間が未定 | 自動再送を廃止。15秒でタイムアウトし、同じ回答を手動で再送する |
| D09 | 500名の総数と同時利用の保証が混同されうる | 500完了セッション・2,000試行の整合性を検証。同時500名や速度保証は対象外 |
| D10 | 刺激の長さ・丁寧さの確認に合否基準がない | 全文固定、提案本文一致、文数・敬体統一、文字数差の記録を必須とする |

D03・D04は、当初検討した「30日以内の完了確認の例外許可」を置き換える最終判断です。確認用のトークンを24時間超で保持する仕組みは追加しません。
D05は、旧版への互換対応や更新待ちの運用を必須にする案を採用しなかった判断です。

## 判定可能な基準

各項目について対象コミット、環境、実施日、入力・操作、期待結果、実際の結果、証拠の場所を記録します。結果は合格・不合格・未実施を区別し、必須項目の未実施を合格に数えません。

| ID | 入力・操作 | 合格条件 |
| --- | --- | --- |
| AC01 | 新規チェックアウトから依存導入、ローカル起動、ビルド | 手順を再現でき、ローカルDBにのみ保存され、ブラウザー成果物に管理認証がない |
| AC02 | S01〜S04の両条件全文を比較 | 状況・提案本文・質問・尺度が場面内で共通。差は前置きのみ。両前置きの文数と敬体を揃え、文字数と差を比較表に記録する |
| AC03 | 群割り当てと提示順生成を検証 | 各50%の独立した2群割り当て。4場面が各1回・全て同じ群。人数調整なし。乱数の制御による分岐検証と生成処理の確認を行い、実測人数の完全な半々を要求しない |
| AC04 | 同じ開始要求を再送・同時送信 | DBに1セッションだけ保存。群・順列・刺激・期限が一致する。作成前にID・トークンをローカルへ保持し、応答消失後も再発行しない |
| AC05 | 未同意、受付停止、無効トークン、未登録trialId、不正尺度を送信 | 新規収集や不正保存を拒否。尺度は1〜7の整数のみ。無効トークンで回答・存否を返さない。停止前に作成済みの有効セッションは保存できる |
| AC06 | 2尺度を未選択・片方のみ・両方選択で確定 | 両方選択時だけ確定。値1と7がDB・CSVでも1と7になる。条件名や技術的な詳細を課題画面に表示しない |
| AC07 | 確定時のローカル保存を失敗させる | 次の場面へ進まず、保存できなかったことを案内。成功時はローカル保存後に次へ進む |
| AC08 | 同一試行を同時送信し、次に異なる内容を送信 | 同一回答は1行に収束し、既存再送は200。異なる内容は409で元の回答・メタデータを維持する |
| AC09 | 3回答、4回答、4件目の保存処理失敗、最終応答消失を検証 | 3件では未完了。4件目の保存と完了が一体で成功または失敗し、4件だけ保存された未完了状態を残さない。応答消失でもDBは完了、同一再送で完了時刻が変わらない |
| AC10 | 通信切断、応答待ち15秒、429、503、その後の復旧 | 自動再送なし。回答保持・手動再送案内があり、復旧だけでは送らない。手動再送で同じDTOを送信。有効な429待機指定と24時間期限を守る |
| AC11 | 1場面目の回答前、途中場面、確定後の保存待ちでリロード・タブ閉鎖 | 再開選択後に同じmanifestとAPIを照合。確定回答は再回答せず、未保存分は手動再送。未確定場面だけ再提示する |
| AC12 | 課題を中断して再提示する場合と、全回答確定後に保存確認だけ再開する場合 | 前者は`resume_count`が増え、同じ場面の再提示なら`presentation_attempt`も増える。後者は確定DTOを変更せず、課題再開なしの感度分析から除外しない |
| AC13 | 同じ公開元で開始前・途中・進捗消去時に2タブを操作 | 同じ進捗領域を同時に変更できない。ロックを取れないタブは案内のみ。別IDを発行して保存キーを上書きしない |
| AC14 | サーバー時刻が再開期限の直前・一致・直後、クライアント時計の変更 | サーバー基準で期限未満のみ再開・送信可能。一致以降は正しい認証でも410。DBの完了状態は維持。アプリ動作中または次回アクセス時に期限切れの端末データを消す |
| AC15 | 完了保存の応答を受信、または期限内照合で完了確認 | 確認後にお礼を表示し、端末の回答・トークン・キューを消す。確認前に保存成功を断定しない |
| AC16 | 固定した500完了セッション・2,000試行を取得 | 試行CSVのID・値・件数がDBと一致。別のセッションCSVは500行。token・hashを出力しない |
| AC17 | 追加で0回答、1〜3回答、24時間経過の未完了、30日経過のデータを取得 | 試行CSV既定は完了のみ。セッションCSVは保持期限内の全参加者を含み、期限内未完了と期限切れ未完了を区別。30日期限到達データは両CSVから除外する |
| AC18 | 30日期限の直前・一致・直後と削除失敗後の再実行 | 期限一致以降は取得対象外。毎時処理で親子行が連動削除され、失敗後の再実行で残りを削除できる。復元後も同じ期限を適用する |
| AC19 | Chrome安定版で幅1024 CSS pxと通常のPC幅、キーボードのみで操作 | 説明から保存確認まで完遂でき、文字・選択肢・フォーカスが確認できる。幅不足・必須機能不足は開始前に案内。OS・ブラウザー版・表示幅を記録する |
| AC20 | React StrictModeで課題開始、画面更新、離脱 | 二重開始・二重確定・入力消失がなく、古い実行のイベント・タイマー・通知が後続画面を変更しない |
| AC21 | Wranglerで公開し、公開URLで同意からCSV取得まで操作 | 公開D1に4回答が保存され、完了者として両CSVで照合できる。開発PC停止後も動作する。公開環境で手動再送・再開・期限削除の動作とCron実行証拠を確認する |

API・DBの合否は実際のローカルD1による統合試験を含めます。ブラウザーの操作・再開はE2Eで確認します。期限境界は試験用時計や検証用データで再現でき、実時間で24時間・30日待つ必要はありません。公開Cronについては設定の存在だけで実行成功とみなしません。

同時試行保存・重複・応答消失は整合性試験です。同時利用者数や応答時間の性能保証を追加するものではありません。

## 対象外と残る準備

- 参加途中の仕様更新、更新をまたぐ再開、複数schemaへの互換対応、データ移行。
- Chrome以外の動作保証、別端末・別ブラウザーへの再開、失われた端末データの復旧、24時間後の完了確認。
- 同時500名・応答速度の保証、募集と同時進行する厳密なCSVスナップショット。
- 尺度の妥当性、操作の効果、研究上の新規性の証明。文字数差に数値の合否閾値は設けない。
- 研究責任者・参加条件・説明同意文・必要人数・除外規則・予備実施は、実参加者募集前に確定する。約5分は実測済みの保証値ではない。

今回の監査は文書内の整合性と判定可能性を対象に、Reviewer・Subworkerを起動せず実施しました。外部資料の記載やサービス料金・制限の再検証、アプリの実行試験は実施していません。実装計画にある公式情報の確認は公開時の作業として残します。

## 文書監査の終了判断

同期質問でD01〜D10の最終判断を確認し、研究計画・データ契約・アーキテクチャ・実装計画・READMEに反映しました。15秒の通信待ちと刺激の比較基準も追加確認済みです。初期に検討した完了確認例外・自動再送・旧版互換保証を、現在の必須要件として残していません。

文書7件のローカルリンク先、コードフェンス、AC01〜AC21の識別子の一意性、差分の空白エラーを確認しました。Hello Worldの手順は既存の実装記録として維持しています。
今回発見した仕様上の判断事項が決定または対象外として明示され、必須動作に判定方法が対応したため、文書監査を終了します。AC01〜AC21の実装受け入れは本監査では全て未実施であり、技術完成や募集可能との判定は行っていません。
