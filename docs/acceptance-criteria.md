## 完成の定義

Wranglerで公開し、公開URLで説明・同意、4場面の回答、DB保存、CSV取得、同じ仕様での通常の途中再開を確認できることを技術完成とします。障害時の挙動と期限削除はローカルで検証し、公開Cronは設定確認までを完成条件とします。定期実行の成功確認は公開後の運用確認として残します。デプロイコマンドの成功だけでは完成としません。

現在のHello Worldの実装・検証記録は[開発・デプロイ手順](deployment.md)にあります。1試行の接続確認を、4場面の実験の合格証拠に代用しません。
実参加者の募集開始、研究上の必要人数・分析規則の確定、予備実施は別の研究準備です。今回はローカルと合成データ用の公開Worker/D1の1組で完成可とし、公開先を2つ用意することは必須にしません。公開デモは合成データの接続・操作確認用途と明示します。実参加者の収集を始める際は研究準備と検証用データとの環境分離を改めて行います。

本書は合否判定、[データ契約](data-contract.md)は保存・APIの動作、[研究計画](research-plan.md)は研究上の位置づけを記述します。説明が食い違う場合は合格にせず、文書を整合させてから判定します。

## 判定可能な基準

対象コミット・環境・実施日と、自動テスト・手動確認の結果を1つの確認記録にまとめます。項目ごとの証拠資料は必須にしません。結果は合格・不合格・未実施を区別し、必須項目の未実施を合格に数えません。既存のテスト結果や通し確認で複数項目を確認して構いません。

| ID | 入力・操作 | 合格条件 |
| --- | --- | --- |
| AC01 | 新規チェックアウトから依存導入、ローカル起動、ビルド | 手順を再現でき、ローカルDBにのみ保存され、ブラウザー成果物に管理認証がない |
| AC02 | S01〜S04の両条件全文を比較 | 状況・提案本文・質問・尺度が場面内で共通。差は前置きのみ。両前置きの文数と敬体を揃え、文案を目視確認する。文字数比較表は必須にしない |
| AC03 | 群割り当てと提示順生成を検証 | 各50%の独立した2群割り当て。4場面が各1回・全て同じ群。人数調整なし。乱数の制御による分岐検証と生成処理の確認を行い、実測人数の完全な半々を要求しない |
| AC04 | 同じ開始要求を再送・同時送信 | DBに1セッションだけ保存。群・順列・刺激・期限が一致する。作成前にID・トークンをローカルへ保持し、応答消失後も再発行しない |
| AC05 | 未同意、無効トークン、未登録trialId、不正尺度を送信 | 新規収集や不正保存を拒否。尺度は1〜7の整数のみ。無効トークンで回答・存否を返さない。新規受付停止と既存参加の継続を分ける制御は実収集前へ延期する。 |
| AC06 | 2尺度を未選択・片方のみ・両方選択で確定 | 両方選択時だけ確定。値1と7がDB・CSVでも1と7になる。条件名や技術的な詳細を課題画面に表示しない |
| AC07 | 確定時のローカル保存を失敗させる | 次の場面へ進まず、保存できなかったことを案内。ローカル保存後にAPIへ送り、DB保存成功の確認後に次へ進む |
| AC08 | 同一試行を同時送信し、次に異なる内容を送信 | 同一回答は1行に収束し、既存再送は200。異なる内容は409で元の回答・メタデータを維持する |
| AC09 | 3回答、4回答、4件目の保存処理失敗、最終応答消失を検証 | 3件では未完了。4件目の保存と完了が一体で成功または失敗し、4件だけ保存された未完了状態を残さない。応答消失でもDBは完了、同一再送で完了時刻が変わらない |
| AC10 | 通信切断、応答待ち15秒、429、503、その後の復旧 | 自動再送なし。次の場面へ進まず、確定回答を保持して手動再送を案内し、復旧だけでは送らない。手動再送で同じDTOを送信。有効な429待機指定と24時間期限を守る |
| AC11 | 1場面目の回答前、途中場面、確定後の保存待ちでリロード・タブ閉鎖 | 再開選択後に同じmanifestとAPIを照合。確定回答は再回答せず、未保存分は手動再送。未確定場面だけ再提示する |
| AC12 | 課題を中断して再提示する場合と、全回答確定後に保存確認だけ再開する場合 | 前者は`resume_count`が増え、同じ場面の再提示なら`presentation_attempt`も増える。後者は確定DTOを変更せず、課題再開なしの感度分析から除外しない |
| AC13 | 同じ公開元で2つ目のタブを開き、元のタブを閉じて再開 | 2つ目のタブでは開始・進捗変更ができず、案内を表示する。元のタブを閉じた後に再開できる。単一タブ制御は維持するが、開始前・途中・進捗消去の各段階で独立した競合試験は要求しない |
| AC14 | サーバー時刻が再開期限の直前・一致・直後、クライアント時計の変更 | サーバー基準で期限未満のみ再開・送信可能。一致以降は正しい認証でも410。DBの完了状態は維持。アプリ動作中または次回アクセス時に期限切れの端末データを消す |
| AC15 | 完了保存の応答を受信、または期限内照合で完了確認 | 確認後にお礼を表示し、端末の回答・トークン・送信待ちを消す。確認前に保存成功を断定しない |
| AC16 | 両群の完了セッションを含む少数の固定した合成データを取得 | 完了試行CSV・未完了試行CSV・全セッションCSV・抽出メタデータの4ファイルを固定出力し、各CSVのID・値・件数がDBと一致。空のCSVもヘッダーを出力する。完了者は各4試行。token・hashを出力しない。500件規模の取得は今回の完成条件にしない |
| AC17 | 追加で0回答、1〜3回答、24時間経過の未完了、30日経過のデータを取得 | 完了試行と未完了試行を別CSVへ出力する。セッションCSVは保持期限内の全参加者を含み、期限内未完了と期限切れ未完了を区別。30日期限到達データは全CSVから除外する |
| AC18 | ローカルで30日期限の直前・一致・直後と削除失敗後の再実行 | 期限一致以降は取得対象外。定期削除処理で親子行が連動削除され、失敗後の再実行で残りを削除できる。バックアップ復元の試験は必須にしない |
| AC19 | Chrome安定版の通常のPC幅で、キーボードのみでも操作 | 説明から保存確認まで完遂でき、文字・選択肢・フォーカスが確認できる。小画面ではPC利用を案内し、必須機能不足は開始前に案内。固定幅による開始禁止は設けず、検証したOS・ブラウザー版・表示幅を一括記録に残す |
| AC20 | React StrictModeで課題開始、画面更新、離脱 | 二重開始・二重確定・入力消失がなく、古い実行のイベント・タイマー・通知が後続画面を変更しない |
| AC21 | Wranglerで公開し、公開URLで同意からCSV取得まで操作 | 公開D1に4回答が保存され、完了試行CSVとセッションCSVで完了者として照合できる。開発PC停止後も動作する。通常の途中再開と公開Cron設定を確認する。障害・期限削除のローカル試験を公開で繰り返すことや、Cron実行待ちは必須にしない |

保存・重複・期限などの重要箇所は自動テストで確認し、API・DBの合否は実際のローカルD1による統合試験を含めます。ブラウザーの操作・再開は手動の通し確認でも構いません。期限境界は試験用時計や検証用データで再現でき、実時間で24時間・30日待つ必要はありません。公開Cronの設定確認は実行成功の証明ではないため、実行確認は別途運用で行います。

同時試行保存・重複・応答消失は整合性試験です。同時利用者数や応答時間の性能保証を追加するものではありません。

## 対象外と残る準備

- 参加途中の仕様更新、更新をまたぐ再開、複数schemaへの互換対応、データ移行。
- Chrome以外の動作保証、別端末・別ブラウザーへの再開、失われた端末データの復旧、24時間後の完了確認。
- 500件規模の取得試験、同時500名・応答速度の保証、募集と同時進行する厳密なCSVスナップショット。500件規模の確認は将来の運用前に行う。
- バックアップ復元シナリオの試験。復元を行う際は受付再開前に期限切れ削除を再実行する。
- 尺度の妥当性、操作の効果、研究上の新規性の証明。文字数比較表は研究準備の任意作業とし、文字数差に数値の合否閾値は設けない。
- 研究責任者・参加条件・説明同意文・必要人数・除外規則・予備実施は、実参加者募集前に確定する。約5分は実測済みの保証値ではない。

今回の監査は文書内の整合性と判定可能性を対象に、Reviewer・Subworkerを起動せず実施しました。外部資料の記載やサービス料金・制限の再検証、アプリの実行試験は実施していません。実装計画にある公式情報の確認は公開時の作業として残します。
