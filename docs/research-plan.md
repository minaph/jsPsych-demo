# 研究計画

基準日: 2026-09-11。研究実施前の草案です。倫理審査、必要人数の確定、研究上の新規性の確認は完了していません。
ユーザーが選択した要件はREADMEにまとめ、以下の場面数・質問文・分析方法は実装を具体化する設計案として示します。

## 問いと位置づけ

**同じ休日の提案に、希望の理解を示す前置きを添えると、中立な前置きの場合より「理解された感覚」が高くなるか。**

大澤研究室が扱う人とエージェントのコミュニケーションを背景とした企画です。
今回は言語表現に対する人の評価を調べます。AIの実際の意図推定能力、長期的な信頼、実際に提案へ従う行動は測りません。
固定文章を用いるため、実験説明でも「その場でAIが生成する」「実際の担当者が応答する」とは説明しません。

参照先:

- [大澤研究室](https://osawa-lab.com/): 研究室の背景。今回の実験の効果を裏づける資料としては扱いません。
- [「しりとり」に含まれる手がかりが「準」自然言語の意味推測に与える影響、2023年](https://www.jstage.jst.go.jp/article/jcss/30/3/30_2023.024/_article/-char/ja/): 理解と主観的確信を分ける関連研究。今回の前置き操作を検証した研究ではありません。

この計画にはGRADE Evidence-to-Decision frameworkを参考にした意思決定支援を用いました。
研究の意義、実装負担、参加者負担、推論の限界を比較するための利用であり、正式なGRADE評価や研究承認を意味しません。

## 仮説と測定

主仮説は「理解を示す前置きの条件で、理解された感覚の評価が高い」です。
効果が存在することを前提にせず、両側の区間推定・検定で低下や差が小さい可能性も扱います。

| 指標 | 質問文の案 | 役割 |
| --- | --- | --- |
| `understanding` | この応答は、この場面での私の希望を理解していると感じる。 | 主要評価項目 |
| `usefulness` | この提案は、この場面での私にとって役に立つと感じる。 | 副次的・探索的評価項目 |

両項目とも1「まったくそう思わない」〜7「とてもそう思う」。未選択で開始し、2項目の回答を必須とします。
項目の順序は理解感、有用性の順で固定します。
これは本デモ用の単一項目であり、妥当性を確認済みの心理尺度とは表示しません。
有用性も操作の影響を受ける可能性があるため、主要分析で機械的に共変量として調整しません。

## 条件と刺激

| 条件ID | 前置き | 提案本文 |
| --- | --- | --- |
| `acknowledge` | 指定された希望を言い換え、理解を示す | 場面内では共通 |
| `neutral` | 提案を行うことだけを知らせる中立な案内 | 場面内では共通 |

比較は「前置きあり / 完全になし」ではなく、前置きの内容の違いです。
長さ、丁寧さ、文の数を可能な範囲で揃え、実装の表示ラベルもこの操作と一致させます。

例:

> 場面: 明日の午後は予定がありません。最近疲れているので、静かに過ごしたいと考えています。あなたがこの状況にいると想像して、次の提案を読んでください。

| 要素 | 文案 |
| --- | --- |
| 理解を示す前置き | 静かな時間を過ごして、疲れを癒やしたいのですね。 |
| 中立な前置き | 明日の午後の過ごし方について、一つご提案します。 |
| 両条件で共通の提案 | 近所の落ち着いた喫茶店で、本を読みながら過ごすのはいかがですか。 |

8場面の題材案:

| 場面ID | 指定する希望 | 提案の方向 |
| --- | --- | --- |
| S01 | 疲れているので静かに休みたい | 喫茶店で読書 |
| S02 | お金をあまり使わず気分転換したい | 近所の公園で散歩 |
| S03 | 無理なく体を動かしたい | 平坦な遊歩道を短く歩く |
| S04 | 画面を見る時間を減らしたい | 植物を眺めながら過ごす |
| S05 | 手を動かして何か作りたい | 家にある紙で簡単な工作 |
| S06 | いつもと違うことを学びたい | 身近な展示を見に行く |
| S07 | 友人とゆっくり話したい | 静かな場所でお茶をする |
| S08 | 少しの空き時間を楽しみたい | 近所の店まで短い散歩 |

全文は実装段階で作成し、8場面とも提案の適合性・具体性を確認します。
刺激は研究者が作成したテキストとして固定し、実験中の自由入力、音声、画像、外部生成APIは使いません。

## 割り当てと順序

- 1人につき8場面を各1回提示し、`acknowledge` 4場面、`neutral` 4場面とします。
- L0ではS01/S03/S05/S07を`acknowledge`、残りを`neutral`とします。L1は逆にします。
- サーバーは開始時にL0/L1を等確率で割り当て、場面順をランダム化して具体的な順列を保存します。人数の厳密な同数割り当ては保証しません。
- 同じ参加者に同じ場面の両条件は見せません。場面に条件が固定されないよう、参加者間で対応を入れ替えます。
- 再開後も条件、場面順、刺激バージョンを維持します。回答済みの場面は繰り返しません。
- 2項目が確定していない場面は最初から提示し直します。再提示は記録し、反応時間は再開後の提示から測り直します。
- 条件名や仮説は課題画面に表示しません。全員が両条件を見るため、操作に気づく可能性は限界として残ります。

## 参加者の流れ

1. PC向けであること、目的、約5分の所要時間、保存・中断の扱いを確認する。
2. 説明を読んで同意する。同意しない場合は回答収集を開始しない。
3. 指定された場面を自分の状況として想像することと、7段階評価の使い方を読む。
4. 8場面について、状況・提案・2つの評価項目を同じ画面で読み、回答を確定する。
5. 各場面の確定後に保存を開始する。最終画面では全件の保存と完了登録を待つ。
6. 保存確認後、「ご協力ありがとうございました」と簡素な完了表示を出す。

個人の結果比較、全体集計、技術解説、デモ用の条件切り替えは設けません。
所要時間の仮配分は説明・同意・操作説明に約1分、8場面に約3分半、完了に約30秒です。
これは実測値ではなく、通信と予備実施を踏まえて調整する目標です。

## 規模、予備実施、分析

運用想定は100〜500名。計画上の分析例には完了者200名を仮置きしますが、人数は確定していません。
募集費用や謝礼処理はアプリに含めません。

予備実施案は5〜10名です。中央値だけでなく長くかかる例、説明の誤解、尺度の天井・床への偏り、文章の不自然さを確認します。
少人数の予備データの効果量だけで本実験の人数を決めず、意味のある最小差、参加者内差のばらつき、脱落見込みから必要人数または感度分析を定めます。
500名でも必要精度が得られない場合は、検証目的を探索的な位置づけへ変更するか、研究計画を再検討します。

主要分析の実装案:

1. 完了済み、8場面が一意に保存済み、各条件4場面、尺度値が1〜7の参加者を抽出する。
2. 各参加者について、理解感の条件別平均と差 `acknowledge - neutral` を求める。
3. 差の平均と95%信頼区間、対応のあるt検定を報告する。分析単位は参加者で、8試行を8人と数えない。
4. 有用性は同様に集計するが探索的に扱い、主要仮説の成立判定には使わない。
5. 中断・再開のある参加者を含む主分析と、再開がない参加者のみの感度分析を比較する。

7段階を数値として集計する仮定と、8場面の内容への依存を明示します。
場面効果を含む混合モデルなどは研究として必要になった場合の拡張とし、今回の最小デモ実装の必須条件にはしません。
途中回答は未完了として別に集計し、主要分析へ混ぜません。短時間回答などによる除外基準は本募集前に定め、結果を見て変更しません。
ランダムIDは人物の本人確認ではありません。複数回参加を完全には防げない点も残ります。

## 公開前に確定する事項

以下は、実装計画を作成するためには保留可能ですが、実参加者を募集する前には確定が必要です。

- 研究・デモの責任者と問い合わせ先。
- 対象年齢、日本語理解などの参加条件、募集経路、謝礼の有無。
- 所属先で必要な倫理手続きと説明・同意文。承認済みとは記載しない。
- 保存済みの途中回答の利用目的、同意撤回・削除相談への対応方法。
- 固定文章を提示すること、想像した状況への評価であることの説明。
- ブラウザー内保存、24時間の再開期限、サーバー上の30日保持、コピー・バックアップの扱い。
- 刺激全文、所要時間、必要人数、分析・除外規則。

責任者や連絡先の仮文字列を残したまま参加受付を有効にしない構成にします。
本研究で30日を超える保存が必要になった場合、デモとは別の設定・保存先・同意文を用意してから実施します。
